# 软件需求规格说明

**产品名称**：dsh-request-doctor（请求急救员）
**产品标识**：dsh-request-doctor
**版本**：0.11.0

---

## 1 引言

### 1.1 标识

本文档适用于 dsh-request-doctor 插件。该插件以 npm 包形式发布，模块名 `dsh-request-doctor`，运行于 DeepSeek Harness（以下简称 DSH）宿主进程内，属于 Host 端插件，无客户端一半。

### 1.2 系统概述

DSH 是一个以 Cordis 插件框架组织的智能体运行时。插件通过组合包（bundle）安装进某个 profile，由 Loader 在启动时组合。系统存在两类对用户可见的失败：

1. **请求失败**：模型请求、工具调用、浏览器载体请求在传输层、承载层或超时层失败，本身可重试，但运行时默认不重试或重试策略不足以覆盖。
2. **版本不匹配**：已安装插件声明的 DSH 依赖范围与当前运行时版本不符，导致插件被 Loader 拒绝组合，或安装时被管理器拒绝。

本插件对这两类失败自动处置，无需人工介入。

### 1.3 文档概述

本文档规定功能需求、外部接口需求、性能需求、设计约束、软件质量特性与验收准则。安全与隐私需求见第 5 章。

## 3 需求

### 3.1 所需状态和方式

插件在 DSH 宿主进程内以单例方式运行，生命周期由 Cordis 上下文管理。插件被禁用或卸载时，所有定时器、进行中的重试、监听器必须一并释放，不得残留。

### 3.2 功能需求

#### FR-1 模型请求自动修复

当 `agent/request-error` 事件触发时：

- FR-1.1 必须在**所有下游监听器放弃重试之后**才接管，避免与 provider 自有重试策略形成双重重试链。
- FR-1.2 必须区分"客户端原因"与"服务端原因"，仅修复前者。
- FR-1.3 客户端原因必须覆盖下列形态，并归入对应的处置策略：

| 形态 | 归类 | 处置 |
| --- | --- | --- |
| 传输中断、流式断连、socket 重置 | `transport` | 退避重试 |
| SSE 长连接超时、事件流被截断 | `stream` | 退避重试 |
| 超时 | `timeout` | 退避重试 |
| 空响应 | `empty` | 退避重试 |
| 上下文累加超限、裁剪策略失效 | `overflow` | 先压缩再重试 |
| 压缩后仍超限、压缩自身打转 | `compaction-loop` | 先修历史，再重试 |
| 会话历史损坏、规则文件解析失败、配置 JSON 解析失败 | `history` | 先修历史，再重试 |
| Wire API 版本不匹配 | `protocol` | 有限重试 |
| 角色字段不被接受、客户端追加独有参数、tool_call 格式不符 | `protocol` | 有限重试 |
| 模型 ID 写死、模型能力判断错、模型列表缓存过期 | `model` | 先刷新模型目录，再重试 |
| Header 构造错误、OAuth 会话过期、本地缓存 token 失效、不自动刷新 | `auth` | 先刷新凭据，再重试 |
| 多 Key 轮换挑到失效项、Provider 侧缓存了旧凭据 | `auth` | 先刷新凭据，再重试 |
| MCP 子服务独立鉴权失败 | `auth` | 先刷新凭据，再重试 |
| MCP 会话关闭、握手失败、子服务未起 | `mcp` | 退避重试 |
| `PI_AI_ERROR` | `provider-error` | 退避重试 |
| 端口占用、句柄耗尽、内存不足、子进程崩溃、本地中转服务崩溃 | `local-env` | 退避重试 |
| 权限不足、路径不存在、磁盘写满、沙箱拦截 | `local-blocked` | **不重试** |
| TLS 证书校验失败、自签名、证书过期 | `tls` | **不重试** |
| 配额耗尽、欠费、限流、内容审核、图片超限 | `quota` / `policy` / `image` | **不处置** |

- FR-1.4 服务端原因不得处置，包括：配额耗尽、账号欠费、限流、上游 5xx、内容审核拦截、图片超限。
- FR-1.5 重试必须采用有界指数退避，带抖动，且受单步预算约束。
- FR-1.6 上下文超限时，必须先尝试压缩与工具结果裁剪，再重试。
- FR-1.7 适配器缺失时，必须先触发版本修复，修复无效则不重试。
- FR-1.7a 凭据失效**不得**走版本修复：重装插件不会让过期 token 变新。应先请求本机凭据层刷新，再重试。
- FR-1.8 重试过程必须以既有的 `llm/retry` / `llm/retry-started` 会话事件记录，**不得新增会话事件类型**。
- FR-1.9 同一处失败（按轮次、步骤、provider、类别定位）同时只允许一个重试在飞，避免并发重试叠加。
- FR-1.10 压缩或修历史连续两轮未见进展时，必须停止重试并留下记录，不得无限循环。
- FR-1.11 鉴权类失败的重试额度必须独立于普通重试额度，取值更小。
- FR-1.12 不可重试类（证书、权限、路径、磁盘）必须直接放弃，不得进入退避。

#### FR-2 工具调用自动修复

当 `tools/execute` 事件触发且结果为瞬时失败时：

- FR-2.1 仅允许重放**只读类**工具，白名单可配置。
- FR-2.2 有副作用的工具（命令执行、写文件、发送消息等）一律不得重放。
- FR-2.3 重放次数受 `maxToolRetries` 约束。
- FR-2.4 同名同参的调用连续出现次数受 `maxRepeatedToolCalls` 约束；超过后**不得再重放**，避免把宿主侧失效的循环检测放大成重放风暴。

#### FR-3 浏览器载体自动修复

当 `connection/request` 事件在响应头发出前失败，且属于瞬时传输错误时：

- FR-3.1 必须替换为 `503` 并附 `retry-after`，使前端自身恢复逻辑可以重发。
- FR-3.2 响应头已发出或响应体已结束时，必须原样抛出原错误，不得写出残缺响应。

#### FR-4 版本不匹配自动修复

- FR-4.1 必须发现**全部**不兼容插件，而非只处理首个。
- FR-4.2 发现来源必须覆盖：Loader 拒绝的包、已启用但未被拒绝的包、已禁用但已安装的包、安装时被延迟处理的包。
- FR-4.3 修复前必须审计：该插件所导入的每个 `@deepseek-ai/*` 符号在现行运行时中是否仍然存在。
- FR-4.4 审计通过者才可修复；审计未通过者只报告，不修改。
- FR-4.5 修复方式为**兼容环境**：在插件目录内建立嵌套 `node_modules`，其中每个被重定位的包是一个声明旧版本号的垫片，转发到现行实现。
- FR-4.6 修复必须同时对齐插件自身 manifest 中的 DSH 依赖声明，因为 Loader 在组合前读取该文件。
- FR-4.7 **不得绕过版本检查**：修复后的声明必须真实满足当前运行时。
- FR-4.8 现行运行时不存在的符号**不得伪造**。必须为插件安装它期望的那份真实旧版本；旧版本也没有时如实报缺。
- FR-4.12 **不得使用占位实现**。缺符号只有两种出路：装真实旧版本，或如实拒绝。
- FR-4.9 环境建成后必须**逐条核对**插件所需符号是否真能提供；核对不通过不得计为已修复。
- FR-4.10 核对无法进行时（目标文件不可读）不得判为失败，应单独记录为未核对。
- FR-4.11 扫描须识别「垫片存在但内容不对」的情况并重新适配。

#### FR-5 不兼容插件安装支持

- FR-5.1 必须提供在安装前预置兼容环境的手段，使管理器的版本检查按其自身规则通过。
- FR-5.2 安装失败或被取消时，必须完整回滚到候选目录原状。
- FR-5.3 仅支持本地目录；注册表包字节尚未落盘，必须明确报告为不支持，不得静默失败。

#### FR-6 状态与诊断

- FR-6.1 必须提供 `/doctor` 命令，输出各类修复计数与最近事件。
- FR-6.2 `/doctor install <路径>` 执行安装前预置。
- FR-6.3 诊断快照可选写入文件，写入不得阻塞事件循环。

### 3.3 性能需求

- PR-1 稳态下后台扫描的 CPU 与 I/O 开销必须可忽略，采用退避策略。
- PR-2 已适配插件必须从后续扫描的审计集合中自然退出，不得反复审计。
- PR-3 任何长期存活的数据结构必须有界。
- PR-4 定时器必须不阻止进程退出。

### 3.4 设计约束

- DR-1 不得依赖 `node_modules` 之外的第三方包；插件须在无额外依赖的 profile 中运行。
- DR-2 不得调用 `setBundleEnabled` / `removeBundle` 操作本插件扫描范围之外的插件。
- DR-3 路由冲突只报告，不处置——归属用户决定。
- DR-4 不得新增会话事件类型，避免未知事件被读取方拒绝。
- DR-5 源码质量须满足 GB/T 45717-2025 度量限值，见《软件质量度量报告》。

### 3.5 属性

- AR-1 平台：Windows / macOS / Linux，Node.js ≥ 20。
- AR-2 运行时：DSH 0.2.x。
- AR-3 并发：同一 profile 内单实例；修复过程以互斥标志防止重入。

## 5 安全与隐私

- SR-1 插件不读取、不传输任何凭据内容；仅判断凭据相关错误码。
- SR-2 插件不外发任何数据；全部处理在本地进程内完成。
- SR-3 修改插件目录前必须备份原 manifest，备份文件名为 `package.json.request-doctor-original`。
- SR-4 删除兼容环境时只删除本插件创建的包，不得删除插件自带的依赖。
- SR-5 诊断快照默认不写文件；启用后内容限于计数、事件类别与配置项，不含请求体。

## 6 注释

- 6.1 术语
  - **兼容环境**：插件目录内嵌套的 `node_modules`，含声明旧版本号的垫片包。
  - **垫片（shim）**：只做 `export *` 转发的最小包。
  - **审计**：判定插件所需符号在现行运行时是否存在的过程。
  - **退避**：重试间隔按指数增长并加抖动。
- 6.2 待定事项
  - 安装前预置目前需显式调用 `/doctor install`；拦截 `install_bundle` 工具调用可进一步自动化，但会改变既有工具行为，需单独确认。
