# 软件安装部署说明

**产品名称**：dsh-request-doctor（请求急救员）
**版本**：0.11.0
**编制依据**：GB/T 8567-2006《计算机软件文档编制规范》6.7

---

## 1 引言

本文档说明 dsh-request-doctor 的安装、配置、升级、卸载与故障处置。

### 1.1 系统要求

| 项 | 要求 |
| --- | --- |
| 运行时 | DeepSeek Harness 0.2.x |
| Node.js | ≥ 20（随 DSH 提供） |
| 平台 | Windows / macOS / Linux |
| 磁盘 | < 1 MB |
| 网络 | 安装时需要；运行时不外发数据 |
| 第三方依赖 | 无 |

---

## 2 安装

### 2.1 作为组合包安装（推荐）

```bash
dsh plugin --profile <profile> install <本目录绝对路径>
```

或在 DSH 插件管理页中选择本目录安装。

安装后插件立即生效，无需重启。

### 2.2 手动放入 profile

1. 将本目录复制到 `<profile>/node_modules/dsh-request-doctor/`。
2. 在 `<profile>/package.json` 的 `dependencies` 中加入 `"dsh-request-doctor": "link:<本目录>"`。
3. 在 `<profile>/cordis.patch.yml` 中插入：

```yaml
- insert:
    - id: request-doctor
      name: 'dsh-request-doctor'
```

1. 重启 DSH。

### 2.3 安装校验

安装后执行 `/doctor`，应输出修复计数摘要。若插件未激活，检查：

- profile 的 `dependencies` 中是否存在该包；
- `cordis.patch.yml` 中是否已插入条目；
- 日志中是否有 `request-doctor: autoRepair is disabled`。

## 3 配置

配置项均位于 `cordis.patch.yml` 的 `config` 下，全部可选。

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `autoRepair` | boolean | `true` | 总开关。为 `false` 时插件不注册任何监听器 |
| `autoVersionRepair` | boolean | `true` | 是否自动修复版本不匹配 |
| `maxRetries` | number | `12` | 单步模型请求的最大修复次数 |
| `maxToolRetries` | number | `2` | 单次工具调用的最大重放次数 |
| `maxVersionRepairs` | number | `64` | 单轮扫描最多适配的插件数；`0` 表示不限 |
| `maxAuthRetries` | number | `2` | 鉴权类失败的最大重试次数。凭据错误重试很贵，额度单独且更小 |
| `maxRepeatedToolCalls` | number | `3` | 同名同参调用连续出现多少次后停止重放，防止循环被放大 |
| `initialDelayMs` | number | `400` | 首次退避基准，毫秒 |
| `maxDelayMs` | number | `20000` | 退避上限，毫秒 |
| `jitterRatio` | number | `0.25` | 退避抖动比例 |
| `retryableToolPattern` | string | 见下 | 允许重放的工具名正则 |
| `recordRetryEvents` | boolean | `true` | 是否写入会话重试事件 |

默认工具白名单（只读类）：

```
^(read|read_image|glob|grep|web_fetch|web_search|cordis_inspect_.*|browser_(list_tabs|snapshot|get_text|wait|scroll)|db_(query|preview|describe_table|list_tables))$
```

示例：

```yaml
- insert:
    - id: request-doctor
      name: 'dsh-request-doctor'
      config:
        maxRetries: 8
        initialDelayMs: 500
```

## 4 使用

### 4.1 查看状态

```
/doctor
```

输出各类修复计数、当前预算与最近 8 条事件。

### 4.2 安装不兼容插件

当插件因版本不匹配无法安装时：

```
/doctor install <插件目录绝对路径>
```

准备完成后再正常安装。准备只对本地目录有效；注册表包会明确报告不支持。

### 4.3 触发手动扫描

`/doctor` 会顺带执行一轮版本扫描并输出结果。

---

## 5 升级

1. 停止 DSH 或禁用插件。
2. 覆盖安装新版本。
3. 重新启用。

升级后首次扫描会自动重建受运行时版本变化影响的兼容环境，并清理不再需要的垫片。

---

## 6 卸载与还原

### 6.1 还原兼容环境

本插件修改过的不兼容插件，若要恢复原状：

1. 删除该插件目录下的 `node_modules/<被适配的包>`（或整个 `node_modules`，若该目录仅由本插件创建）。
2. 用 `package.json.request-doctor-original` 覆盖 `package.json`。
3. 删除 `.request-doctor-compat.json`。

### 6.2 卸载本插件

```bash
dsh plugin --profile <profile> remove dsh-request-doctor
```

插件释放时会中止进行中的重试、清空所有定时器、刷新诊断快照。已建立的兼容环境**不会**被自动删除——那是其他插件的运行依赖，应由用户决定是否还原。

## 7 故障处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 插件未激活 | 未加入 profile 依赖或未插入补丁 | 检查第 2.2 节三项 |
| 日志出现 `autoRepair is disabled` | 配置关闭 | 移除该配置或设为 `true` |
| 插件显示 `incompatible-version` | 本插件自身的 peer 声明与运行时不符 | 更新到匹配版本 |
| `/doctor install` 报 "not prepared" | 目录不可读、无需修复、或远程包 | 按提示的具体原因处理 |
| 某插件一直不被适配 | 审计未通过 | 执行 `/doctor` 查看拒绝原因；通常是所需符号已被运行时移除 |
| 路由冲突提示反复出现 | 两个插件声明同一 provider | 属于用户决策，本插件只报告 |

## 8 运行开销

| 项 | 说明 |
| --- | --- |
| 稳态 CPU | 趋近于零：后台扫描退避至 30 分钟一次，命中缓存 |
| 内存 | 缓存均有上限（manifest 512、模块图 256、重试链 128） |
| 磁盘 | 仅在发现不匹配时写入垫片，内容未变不落盘 |
| 进程退出 | 所有定时器 `unref`，不阻止退出 |
