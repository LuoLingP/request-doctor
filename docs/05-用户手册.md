# 软件用户手册

**产品名称**：dsh-request-doctor（请求急救员）
**版本**：0.11.0
**编制依据**：GB/T 8567-2006《计算机软件文档编制规范》6.5

---

## 1 引言

本手册面向使用者，说明插件能解决什么问题、如何确认它在工作、以及遇到异常时怎么办。安装步骤见《安装部署说明》。

---

## 2 这个插件做什么

它处理两类"明明该好却坏了"的情况。

### 2.1 请求失败自动重试

网络抖动、服务端超时、模型返回空响应、上下文超长——这些都不是你的操作问题，但默认情况下它们会让一次对话中断。

插件会在判定"这是客户端可以挽回的失败"后自动重试，间隔逐次拉长，避免把对方打得更糟。

**不会重试的情况**（这些是对方或账号的问题，重试无意义）：欠费、限流、服务端故障、内容被审核拦截、图片超限。

**不会重复执行的情况**：会改动手上东西的操作（执行命令、写文件、发消息）一律不重放。只读操作（读文件、搜索、抓网页、看浏览器页面）才会被重放。

### 2.2 版本不匹配自动兼容

DSH 升级后，旧插件可能声明"我只支持 0.2.1-rc.2"，而你现在是 0.2.1-rc.3。默认结果是插件直接不能用，甚至装不上。

插件不会去关掉这个检查，而是**给那个插件搭一个它期望的旧环境**：让它以为自己跑在旧版本上，实际调用的仍是当前版本的实现。

这类似 Windows 的"以兼容模式运行"——不是忽略问题，是提供它需要的环境。

**前提**：插件真正用到的东西必须在当前版本里还存在。如果某个功能已经被彻底移除，插件无法正常工作，插件会明确报告而不是伪装成功。

## 3 怎么确认它在工作

### 3.1 查看状态

在对话框中输入：

```
/doctor
```

会看到类似输出：

```
request-doctor: 3 model, 1 tool, 0 carrier, 2 version repair(s)
budget: 12 model retries per step, 2 tool replays
- 2026-10-27T09:12:44.101Z compat: dsh-workbuddy-connect@0.7.9 given a 0.2.1-rc.3 compatibility environment...
```

- **model**：模型请求的自动修复次数
- **tool**：工具调用的重放次数
- **carrier**：浏览器请求的补救次数
- **version**：完成的插件兼容次数

### 3.2 在对话里看

自动重试会在对话中留下重试记录，与 DSH 自带的重试显示方式一致。

## 4 遇到装不上的插件怎么办

### 4.1 现象

安装插件时提示：

```
Plugin xxx@1.0.0 is incompatible with dsh 0.2.1-rc.3
```

### 4.2 处理

1. 输入准备命令，路径填插件所在目录：

```
/doctor install C:\path\to\your\plugin
```

1. 看到 `prepared ... for this runtime` 表示准备完成。
2. 重新执行安装即可。

### 4.3 准备失败的常见原因

| 提示 | 含义 | 怎么办 |
| --- | --- | --- |
| `only a local directory can be inspected` | 你给的是 npm 包名而非本地目录 | 先下载到本地，再指向该目录 |
| `the package already declares requirements this runtime satisfies` | 本来就能装 | 直接安装，无需准备 |
| `the package imports no DSH package` | 该插件不依赖 DSH，无需兼容 | 若仍装不上，问题不在版本 |
| `cannot provide @deepseek-ai/xxx` | 所需符号已被移除 | 该插件版本过旧，需要作者更新 |

## 5 已装插件突然不能用了

先执行 `/doctor`。

### 5.1 显示被适配了，但仍不正常

兼容环境只保证"插件要用的东西还在"。如果插件内部有别的假设（例如某个行为在新版本中变了），它仍可能表现异常。这种情况需要插件作者更新。

### 5.2 显示 `not approved (incompatible)`

插件需要的某个功能在当前 DSH 版本中已被移除。插件不会伪造它，所以不做适配。升级该插件是唯一解法。

### 5.3 显示 `not approved (review)`

插件与当前版本的差距较大（次版本或无法判定），插件选择不自动处理。

## 6 常见问题

**问：会泄露我的数据吗？**
不会。插件不向外发送任何内容，不读取凭据内容，全部处理在本地完成。

**问：会不会重复执行我的命令？**
不会。会改变状态的操作被排除在重放范围之外。

**问：和我其他插件的重试冲突吗？**
不冲突。如果 provider 自己配置了重试策略，本插件会让位，不会产生两条重试链。

**问：两个插件抢同一个模型路由怎么办？**
插件会提示你，但**不会**替你停用任何一个。那是你的插件，由你决定。

**问：怎么关掉它？**
在配置中设 `autoRepair: false`，或在插件管理页停用。

**问：会不会拖慢 DSH？**
稳态下几乎不消耗资源。后台检查会自动拉长间隔，没有需要处理的情况时最短 2 分钟、最长 30 分钟一次，且命中缓存。

**问：它改动了我的插件文件，怎么恢复？**
每个被改动的插件目录下都有 `package.json.request-doctor-original` 备份，删除兼容环境并还原该文件即可。详细步骤见《安装部署说明》第 6 章。

## 7 词汇

| 词 | 含义 |
| --- | --- |
| 兼容环境 | 给旧插件准备的一套"它期望的版本"的替身 |
| 审计 | 检查插件需要的东西在当前版本里是否还存在 |
| 退避 | 重试间隔逐次拉长，并带随机扰动 |
| 重放 | 重新执行一次工具调用 |

## 6 它会修复哪些失败

判断标准只有一条：**这次失败是不是本机这边能挽回的**。对方侧的问题（配额、限流、内容审核）一律不碰。

| 你看到的失败 | 插件的处理 |
| --- | --- |
| 传输中断、socket 重置、流式断连 | 退避后重试 |
| SSE 长连接超时、事件流被截断 | 退避后重试 |
| 请求超时、返回空响应 | 退避后重试 |
| 上下文超限、裁剪策略失效 | 先压缩与裁剪，再重试 |
| 压缩后仍超限、压缩自己打转 | 先修本地历史，再重试；连续两轮没进展就停手 |
| 会话历史损坏、规则文件或配置解析失败 | 先修本地历史，再重试 |
| Wire API 版本不匹配、角色字段不被接受、客户端多塞参数、tool_call 格式不符 | 有限重试 |
| 模型 ID 写死、模型能力判断错、模型列表缓存过期 | 先刷新模型目录，再重试 |
| Header 构造错误、OAuth 会话过期、token 缓存失效、不自动刷新、多 Key 挑到失效项 | 先请凭据层刷新，再重试 |
| MCP 子服务鉴权失败 | 先刷新凭据，再重试 |
| MCP 会话关闭、握手失败 | 退避后重试 |
| HTTP 400 / PI_AI_ERROR | 退避后重试 |
| 端口占用、句柄耗尽、内存不足、子进程崩溃 | 退避后重试 |
| 权限不足、路径不存在、磁盘写满、沙箱拦截 | **不重试**——缺的是权限或空间，不是时机 |
| TLS 证书校验失败 | **不重试**——重试不会让证书变可信 |
| 配额耗尽、限流、内容审核、图片超限 | **不处置**——这是对方侧的原因 |

三类情况插件会主动停手，避免把问题放大：

1. **同一处失败**同时只跑一个重试，不会越堆越多；
2. 压缩或修历史**连续两轮没进展**就放弃，不会无限循环；
3. 同名同参的工具调用**超过阈值**后不再重放，避免把宿主侧失效的循环检测放大。
